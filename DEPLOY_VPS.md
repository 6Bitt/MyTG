# Запуск 24/7 без карты и без VPS

Выбранный путь — **GitHub Actions**. Проверено по официальной документации:
стандартные раннеры в **публичных** репозиториях бесплатны и не расходуют
квоту (2000 минут касаются только приватных); минимальный интервал cron — 5 мин.

Ограничение, которое надо знать: GitHub **троттлит** cron. Реальный интервал
на практике 15–40 минут вместо 15, иногда пропуски при высокой нагрузке.
Для DeFi-мониторинга это приемлемо.

---

## Шаг 1. Создать публичный репозиторий

Репозиторий создаётся на сайте GitHub вручную (CLI `gh` на машине нет).

1. https://github.com/new
2. **Repository name:** `wallet-watcher` (или любое)
3. **Public** ← обязательно, иначе минуты платные
4. **Не** добавляй README/gitignore/license — они уже есть локально
5. Create repository

## Шаг 2. Запушить код

```bash
cd C:\Code\wallet-watcher
git remote add origin https://github.com/<твой-ник>/wallet-watcher.git
git branch -M main
git push -u origin main
```

При первом push GitHub попросит логин. Пароль — **Personal Access Token**:
Settings → Developer settings → Personal access tokens → Tokens (classic) →
Generate new token → scope `repo` → скопировать.

## Шаг 3. Добавить токен бота в Secrets

Репозиторий → **Settings** → **Secrets and variables** → **Actions** →
**New repository secret**

- **Name:** `BOT_TOKEN`
- **Secret:** токен от @BotFather (тот же, что в `C:\Code\tg-channel-tools\.env`)

⚠️ Токен в коде и в git **не лежит** — проверено, `.env` в `.gitignore`.

## Шаг 4. Включить Actions

Вкладка **Actions** → если спросит про workflow — **Enable**.
Первый запуск: **wallet-watch** → **Run workflow** → force: `true`.
Через 2–3 минуты в Telegram придёт отчёт.

## Шаг 5. Проверить, что расписание работает

Actions → wallet-watch → история запусков. Должны появляться каждые 15–40 мин.

## Как это устроено

```
GitHub Actions (cron */15)
        │
        ├─ восстанавливает history.db из cache
        ├─ ставит Python + Playwright + Chromium
        ├─ run_ci.py решает: quick или full
        │     full — если последний был > 10 ч назад
        ├─ watcher.py выполняет проверку
        └─ сохраняет history.db обратно в cache
```

**Почему `run_ci.py`, а не два расписания:** GitHub задерживает cron на
5–20 минут, поэтому «запуск в 10:00» и «запуск в 10:15» могут прийти
одновременно или с разными опозданиями. Скрипт смотрит на фактическую
историю и сам решает, пора ли делать полный отчёт с DeBank.

## Важные ограничения

| Ограничение | Следствие |
|---|---|
| Cron 15–40 мин вместо 15 | алерт о движении придёт с задержкой |
| Раннер живёт макс. 6 ч (у нас 20 мин) | не проблема |
| Playwright качается каждый запуск (~1 мин) | запуск дольше |
| Cache инвалидируется через 7 дней без обращений | история сбросится, если бот простаивал |
| DeBank блокирует IP облаков (429) | риск выше, чем с домашнего |

### Если DeBank начнёт блокировать
1. Увеличить интервал full: в `run_ci.py` → `w.FULL_INTERVAL_H` (сейчас 10)
2. В `config.json` → `fail_streak_limit` — бот сообщит после N сбоев
3. Проверить вручную из лога Actions

## Команды бота

`bot.py` на GitHub Actions **не работает** — это постоянный процесс, а Actions
запускает задачи по расписанию. Варианты:
- держать `bot.py` локально на ПК (сейчас так и есть)
- уведомления при этом приходят 24/7 из облака — они не зависят от ПК

То есть: **алерты 24/7 из GitHub**, команды `/status` — только когда ПК включён.

## Альтернатива, если карта появится

Oracle Cloud Always Free: настоящий сервер 24/7, 4 ARM-ядра, 24 ГБ RAM.
Тогда `bot.py` тоже работал бы круглосуточно, а cron — секунда в секунду.
Инструкция — в конце файла (шаг «Oracle»), либо попроси, соберу заново.
